# Instance Management via Owner API

How to manage your BuddyPro instance — knowledge base, system prompt, voice clone, roles, onboarding — entirely through the API. No Telethon, no manual Telegram tapping.

The general pattern is always: **edit content in Google Drive (browser) → trigger `/update` via API → optionally `/updateRoles` via API → verify via `/checkSetup` or `/investigateAnswer:` via API**.

## Drive folder structure (read-only mental model)

When the instance was set up, BuddyPro created this structure in your Google Drive. **Don't rename folders or auto-generated docs** — the instance breaks.

```
{Expert Name}/
├── READ ME                    # 8-step setup guide (read-only reference)
├── SYSTEM PROMPT              # AI personality + behavior rules (you edit this)
├── ONBOARDING                 # First messages to new users (JSON array, you edit)
├── INITIATED MESSAGES         # Proactive conversation starters (JSON array)
├── Transcription settings     # Language, keywords, quality toggle
│
├── SOURCES/                   # Primary knowledge — chunked into ~1500 char pieces
│   ├── FILES/                 # Upload: video, audio, PDF, docs, images, ebooks
│   │   └── TRANSCRIPTIONS/    # Auto-generated by /update
│   ├── URLS/
│   │   ├── URL SOURCES        # Google Doc — paste URLs (https only, one per line)
│   │   └── TRANSCRIPTIONS/
│   ├── TEXTS/                 # Google Docs only (no .txt or .md!)
│   │   └── METADATA/
│   └── CONVERSATIONS/         # Created by /teach (not yet implemented)
│
├── RAW SOURCES/               # Knowledge kept WHOLE (no chunking, max 6000 chars each)
│   ├── FILES/, TEXTS/, URLS/  # Same as SOURCES
│   └── READ ME                # Explains RAW SOURCES rules
│
└── ROLES/                     # AI subroles (auto-generated)
    ├── -- LIST OF ROLES --    # Master list
    └── {role_name}            # One Google Doc per role
```

### SOURCES vs RAW SOURCES

| | SOURCES | RAW SOURCES |
|---|---------|-------------|
| Chunking | Split into ~1500 char chunks | Kept whole |
| Max size | No limit | 6000 chars |
| Use for | Long content (books, courses, articles) | Short complete items (recipes, checklists, templates) |
| Cost | Lower (only relevant chunks retrieved) | Higher (whole doc retrieved every match) |
| Retrieval | 10 most relevant chunks per message | Complete documents |

### Content type rules

| Folder | Allowed |
|--------|---------|
| `SOURCES/FILES/` | Video (mp4, mov, avi, webm), Audio (mp3, wav, m4a, ogg), Documents (PDF, DOCX, PPTX, TXT), Images (JPG, PNG — OCR'd), Ebooks (EPUB, PDF) |
| `SOURCES/URLS/` (URL SOURCES doc) | YouTube, Vimeo, websites — one URL per line, **https only** |
| `SOURCES/TEXTS/` | **Google Docs ONLY** — `.txt` and `.md` files are silently ignored |
| `RAW SOURCES/*` | Same rules, plus 6000 char limit |

## Adding knowledge

**The skill cannot upload files to Drive directly** (that's a browser operation). But the skill walks the user through the process and triggers the update via API.

1. **User uploads/pastes content in Drive** (browser)
   - Long-form content → `SOURCES/FILES/`, `SOURCES/URLS/`, `SOURCES/TEXTS/`
   - Short complete items (templates, checklists) → `RAW SOURCES/*`
2. **Trigger `/update`** via API:
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"messages": [{"role": "user", "content": "/update"}]}'
   ```
3. **Wait** — `/update` processes 30 seconds to 5 hours depending on content volume. Bot reports progress every ~15 min. Don't poll the API faster than every 5 min.
4. **Optionally re-generate roles** if knowledge changed significantly:
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"messages": [{"role": "user", "content": "/updateRoles"}]}'
   ```
5. **Verify** the new content is integrated:
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"messages": [{"role": "user", "content": "/investigateAnswer:topic specific to new knowledge"}]}'
   ```
   Inspect the response — the new chunks should appear in the "Relevant source or knowhow" section.

## Removing knowledge

1. **Delete the SOURCE file/URL/text in Drive** — NOT just the transcription (transcription gets auto-recreated from the source).
2. Trigger `/update` via API.
3. The transcription disappears too.

**Refresh re-transcription** (e.g. updated language settings):
1. Delete the **transcription file only** (keep the source).
2. `/update` → source gets re-transcribed.

**Service account caveat:** Auto-transcriptions can sometimes resist deletion ("insufficient file permissions"). Owner deletes manually in browser.

## System prompt management

The SYSTEM PROMPT doc is the AI's "DNA" — identity, voice rules, response patterns, frameworks, guardrails.

### Critical rules

1. **Sent with EVERY message.** Long prompt = higher cost per message for ALL conversations. Keep it lean.
2. **Behavior only, NOT knowledge.** Domain knowledge belongs in SOURCES (retrieved when relevant). System prompt = global rules that should appear on every response.
3. **Markdown is rendered literally.** If you write `## Header` or `**bold**`, users see those characters in the bot's reply. Use XML tags + CAPS for structure.
4. **Edit doc → `/update` → test.** Without `/update`, the change is invisible.

### Edit + verify workflow via API

1. User edits `SYSTEM PROMPT` doc in Drive (browser).
2. Trigger update:
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"messages": [{"role": "user", "content": "/update"}]}'
   ```
3. Test the change with a question that should expose it (use stateless to avoid pollution):
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"x_buddy_saveToHistory": false, "messages": [{"role": "user", "content": "your test question"}]}'
   ```
4. If the change didn't take effect, make the instruction more explicit and try again. Vague rules ("be more direct") don't work; specific rules ("ALWAYS start with: 'Hi friend, '") do.

### What goes WHERE

| Goes into System Prompt | Goes into SOURCES |
|-------------------------|-------------------|
| Tone of voice, signature phrases | Specific frameworks per domain |
| Response pattern (Hook → Diagnosis → Action) | Pricing details, product info |
| Identity, credentials | Case studies, examples |
| Guardrails (no hallucination, disclaimers) | Domain-specific methodology |
| Repeated mistakes to avoid globally | One-off topic corrections |

**Test:** Before adding to system prompt, ask: *„Should this appear in EVERY answer?"* If no → SOURCES.

## Onboarding messages

The `ONBOARDING` doc is a JSON array of welcome messages. Bot picks one randomly when a new user starts.

```json
[
  "Hi V_K_! I'm {Expert} AI — {one line about expertise}. {CTA question}",
  "Hello V_K_! {Different opening}. {Same core info}. {Different CTA}"
]
```

- `V_K_` = user's first name from their Telegram profile
- 2–3 variants = more natural feel; bot picks randomly
- 1 variant = stricter adherence
- Must be **valid JSON** (test in jsonlint.com if unsure)

### Edit + apply via API

1. User edits `ONBOARDING` in Drive.
2. `/update` via API.
3. **Test with a fresh test user** — but `/test:` is blocked over the API. Workaround: send a single message via API with a `user` field that's never been used:
   ```bash
   curl -X POST https://api.buddypro.ai/v1/chat/completions \
     -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"user": "onboard-test-2026-05-07-a", "messages": [{"role": "user", "content": "/start"}]}'
   ```
   Each fresh `user` value triggers a new onboarding flow.

### `INITIATED MESSAGES`

Proactive conversation starters — bot uses these to re-engage users after inactivity. Same JSON format as ONBOARDING. Toggle on/off:
```bash
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "/shouldInitiateMessages:true"}]}'
```

## Roles management

Roles are auto-generated specializations. The bot picks the best role for each user query (based on the last 3 messages).

### How they get generated

1. `/update` processes knowledge → identifies main topics.
2. `/updateRoles` (or `/updateNextRole`, `/updateRole:{name}`) creates one Google Doc per topic in `ROLES/`.
3. Each role gets a 15–20K char description with guidelines and key topics.
4. The master list lives in `-- LIST OF ROLES --`.

### Manual role editing — usually NOT recommended

Per docs: *„In >99% of cases, no manual intervention needed."* Editing role docs has LOW impact because:
- Role docs are large (15-20K chars). Custom additions at the end get diluted.
- AI treats system prompt rules as higher priority than role-doc details.

**Better approach:** Add more knowhow to SOURCES → `/update` → `/updateRoles`.

### When manual editing IS justified

- Role definition is fundamentally wrong (e.g. activates on wrong topics)
- A duplicate role caused by overlapping topic detection
- After major knowledge restructuring

To remove a role: delete its Google Doc, edit `-- LIST OF ROLES --` to remove the entry, then `/updateRoles` to regenerate cleanly.

### Diagnostics via API

```bash
# After the bot answered something, find out which role activated
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "/lastRole"}]}'

# Or — for full inspection (answer + role + knowhow chunks)
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "/investigateAnswer:specific question"}]}'
```

## Voice clone

`/createVoiceClone` works via API, but you need to send the audio sample as a follow-up call within the same profile.

```bash
# Step 1 — request voice clone setup
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "/createVoiceClone"}]}'

# Bot replies: "Send the audio sample now"

# Step 2 — send 30s–2min clean audio
AUDIO_B64=$(base64 -i sample.mp3 | tr -d '\n')
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg b "$AUDIO_B64" '{
    messages: [{
      role: "user",
      content: [{type: "input_audio", input_audio: {data: $b, format: "mp3"}}]
    }]
  }')"

# Step 3 — enable for everybody (or just yourself)
curl -X POST https://api.buddypro.ai/v1/chat/completions \
  -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "/useVoiceCloneForEverybody:true"}]}'
```

**Voice clone cost:** ~2× standard message. With music generation: 2–6×. Set a budget cap with `/enableVoiceWithMusicGeneration:true:{limit}`.

**Audio sample tips:**
- 30 seconds to 2 minutes
- Clean (no music, no background noise)
- Skip intros and outros
- Single speaker
- Same language as the bot will speak

## Transcription settings

The `Transcription settings` doc controls how new audio/video sources are transcribed.

| Setting | Values | Effect |
|---------|--------|--------|
| `Improve transcriptions` | `true` / `false` | `true` = better quality, ~$0.023/min. `false` = verbatim, ~$0.01/min. |
| `Language` | ISO 639-1 (e.g., `cs`, `en`) | Blank = auto-detect. Set explicitly for single-language accuracy. |
| `Keywords` | Comma-separated | Proper nouns, frameworks, jargon. Max 224 tokens (~170 words). |

**Changes apply to NEWLY processed content only.** Existing transcriptions need manual refresh:
1. Delete the transcription file (keep the source) in Drive.
2. `/update` via API.
3. Source is re-transcribed using new settings.

## Pre-launch checklist (via API)

Before opening the instance to real users:

```bash
for cmd in "/checkSetup" "/listInvites" "/stats"; do
  echo "=== $cmd ==="
  curl -s -X POST https://api.buddypro.ai/v1/chat/completions \
    -H "Authorization: Bearer $BUDDYPRO_API_KEY" \
    -H "Content-Type: application/json" \
    -d "$(jq -n --arg c "$cmd" '{messages: [{role: "user", content: $c}]}')" \
    | jq -r '.choices[0].message.content'
  echo
done
```

Resolve all warnings from `/checkSetup` before going live. Common ones:
- System prompt not customized
- No subscription URL set (`/setDefaultSubscriptionUrl`)
- No trial-end message (`/setTrialEndedMessage` — must contain `<LINK>`)
- Bot groups not disabled (Telegram BotFather: `/setjoingroups` → Disable)
- Support email missing (`/setSupportEmail`)

## Decision tree — where to fix what

```
Bot gives WRONG answer
  └─ /investigateAnswer:{question} → check knowhow
       ├─ Knowhow is relevant but answer wrong → fix System Prompt
       └─ Knowhow is missing/irrelevant → add content to SOURCES → /update

Bot uses WRONG style/tone
  └─ Fix System Prompt (voice rules, signature phrases, tone)

Bot activates WRONG role
  └─ Question is ambiguous → rephrase clearer, or
  └─ Consistently wrong → check ROLES/list_of_roles for overlap, delete duplicate

Bot doesn't mention specific framework
  └─ Add rule to System Prompt: "ALWAYS mention {framework} when discussing {topic}"

Bot hallucinates facts
  └─ Add System Prompt rule: "NEVER invent specific numbers or client names"
  └─ Add factual content to SOURCES

Onboarding feels off
  └─ Edit ONBOARDING doc → /update → test with fresh user via fresh `user` field

Bot doesn't respond at all
  └─ Check /stats (credits) → /checkSetup (config) → instance may be paused
```

## Critical warnings

1. **Don't rename folders, subfolders, or auto-generated docs** — instance breaks.
2. **Don't create new folders inside the BuddyPro folder.** Add content only inside the existing structure.
3. **Avoid duplicate content.** Same info in 5 docs = bot less smart, not more.
4. **System prompt = behavior, NOT knowledge.** Domain facts belong in SOURCES.
5. **Service account can't upload files** — has no storage quota. Edit existing docs in Drive instead.
